# Focused code snippets

[简体中文](README.zh-CN.md) · [Guide](../docs/en/README.md)

These `.cs.txt` files are reference fragments, so they do not compile together automatically. Copy only the pieces you need into the `source/ModEntry.cs` generated by the game.

1. Replace every `your.package` with your own stable package ID.
2. Keep `[MiniHeroMod(...)]`, `package.json.packageId`, and the source folder's ID consistent.
3. Register every content class you use in `Load`; content IDs must begin with the package ID followed by a dot.
4. Keep the generated `.csproj`, game references, and DLL output path. Add the required `using` directives and any referenced classes.

| Fragment | Topic |
| --- | --- |
| [01](en/01-entry-and-config.cs.txt) | Entry point and compatibility configuration API |
| [02](en/02-character-trait-and-move.cs.txt) | Character, trait, and starting move |
| [03](en/03-character-treasures.cs.txt) | Character-specific treasure pool |
| [04](en/04-enemies-and-traits.cs.txt) | Enemy and enemy trait |
| [05](en/05-stage-bindings.cs.txt) | Stage, enemies, and allowed characters |
| [06](en/06-stage-music.cs.txt) | Stage music theme |
| [07](en/07-three-region-adventure.cs.txt) | Connecting registered source stages into an adventure |

English and Chinese fragments use the same technical identifiers and formulas, with localized comments and fallback strings. For a bilingual mod, use `localization/en.json` and `zh-Hans.json` through `ModText.Get/Format`. There is no player-facing mod configuration page, so configuration declarations do not create editable menus.

Some fragments refer to types or assets you must supply. The seven fragments are not a complete adventure, build project, or installable package. Follow the [testing checklist](../docs/en/04-testing-and-publishing.md) after integration.
