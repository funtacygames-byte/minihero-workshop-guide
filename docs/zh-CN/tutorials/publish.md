# 把模组分享给其他玩家

[English](../../en/tutorials/publish.md) · [目录](../README.md)

自己的模组已经能玩了，就可以准备名称、介绍和封面，再从游戏上传到 Steam 创意工坊。先用私密可见性检查条目，确认没有问题后再公开。

**开始前：**先用当前版本完整玩一遍自己的内容；如果还只是首课练习，可以继续学习，不急着发布。上传需要游戏连接到已登录的 Steam 客户端。

## 1. 留下一份能正常运行的版本

保存源码，确认 `package.json` 里的包 ID 不变、`version` 对应这次要发布的内容。构建安装，完整退出并重启，再新开一局检查：

- 从哪里进入你的内容，角色和关卡能否找到。
- 主要效果是否与说明一致，冒险能否走到结局。
- 使用的图片、音乐和中英文文本是否正常。
- 暂时退出后继续游戏，进度是否正确。

按自己做的内容选相关检查；例如纯宝物模组不用为了发布再制作一张自定义开始页。更多情况见[调试课](debugging.md)。发布后再改内容，需要提高版本并重新构建。

## 2. 准备封面和介绍

把封面放到自己项目的 `assets` 中，例如 `assets/icons/workshop-cover.jpg`。在 `package.json` 的 `coverAsset` 填这个**包内相对路径**。需要额外展示图时，在 `previewAssets` 中添加对应路径；图片文件也要在包内。

| 图片要求 | 怎么准备 |
| --- | --- |
| 格式 | 真实 PNG、JPG 或 JPEG；改扩展名不算格式转换 |
| 长宽 | 每边不超过 4096 像素 |
| 文件大小 | 每张严格小于 1,048,576 字节（1 MiB） |
| 画面 | 封面清楚表现模组；横向展示图可用 16:9 |

过大的背景图可以另存一份压缩 JPG 作为展示图。游戏里用的原背景不必跟着降画质。构建后再检查诊断，确保路径和图片格式正确。

写介绍时，先说玩家会玩到什么，再说如何进入、需要哪个游戏/API 版本、是否需要新开局、有哪些已知限制。只承诺模组已经提供的功能。

## 3. 打开发布准备并保存草稿

1. 在“开发模组”找到自己的项目，点击该行最右侧的发布包图标，打开“发布准备”。位置可对照[操作配图](../reference/visual-walkthrough.md#2-创建与打开源码)。
2. 填标题、简介、逗号分隔的标签和版本说明。
3. 可见性先选“私密”，检查封面和展示图。
4. 点击“保存草稿”。这只保存填写的信息，不会上传。

草稿和已绑定的 Steam 条目 ID 保存在本机工坊 `State/Publication/<packageId>.json`，其中 `<packageId>` 是自己的包 ID。正常更新时保留它，不要为了重试删除绑定。

## 4. 上传并打开条目检查

准备好后点击“校验并上传 Steam”。游戏先编译和校验包，再上传；缺少资料或图片不合格时，按页面的第一条诊断修正后重试。

上传成功后打开 Steam 条目，检查标题、简介、封面、展示图和可见性。首次发布若提示接受创意工坊协议，点击“Steam 创意工坊协议”，完成 Steam 页面要求。未接受时条目可能仍然隐藏。

本地构建成功、保存草稿、生成导出包，都不等于已经上传。以游戏返回的上传结果和 Steam 条目实际状态为准。没有可用 Steam 环境时，可以先做到本地检查，稍后再上传。

## 5. 用玩家拿到的版本再玩一次

公开前，确认下载的发布版本能安装、启用，完整重启后能进入内容。留意自己是否仍在加载开发机上的本地版本，否则它可能掩盖上传包缺文件的问题。代码包需要玩家在管理页信任并启用。

发布包应包含自己的 Mod DLL、清单、翻译和实际使用的素材。游戏生成的开发引用、`.tmode-sdk`、`source/bin`、`source/obj` 和个人存档不属于发布内容。不要手改 `Builds`、`Installed` 或已经导出的文件；回 `Sources` 修改并重建。

## 6. 以后怎样更新同一条目

在原项目修改内容，提高 `package.json.version`，完成构建和检查后重新打开发布准备。按钮应变为“校验并更新 Steam”，继续使用原来的条目 ID。填写这次的更新说明，再更新。

更新后核对条目的版本说明和展示图，并检查订阅下载的实际内容。若改动影响旧存档，提前写清兼容情况；稳定包 ID、内容 ID 和文本键应继续保留。更多字段见[发布手册](../04-testing-and-publishing.md)，常见失败看[排错](../troubleshooting.md)。
