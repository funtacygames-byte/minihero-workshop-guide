# 打包、发布与更新

[English](../../en/tutorials/publish.md) · [目录](../README.md)

教程修订 2 · Mod API 1.8.0 · 2026-10-13 · [验证范围](../reference/versions.md)

目标：从已验收的 Sources 构建一份可安装包，完成发布准备，并理解 Steam 上线验证与本地导出的区别。这篇是操作流程，本次教程重写不替你发布任何模组。

前置：完成对应任务的玩法与资源检查。修改 `package.json` 版本和发布说明；发布素材与条目字段在游戏发布准备页填写。

## 1. 冻结待发布版本

从 Sources 重新构建安装，使用同一版本完成最终检查。包 ID 保持稳定；更新 `version` 时同步修改说明。C# 变更完整重启并新开局验证。至少走完入口、角色、关键触发、出口、失败路径、场景重置、保存恢复、中文英文与缺资源回退。

逐项标准见[测试总览](../04-testing-and-publishing.md)。把构建成功、真实加载、玩法检查和未测部分分别记录；不要把“无编译错误”写成全部通过。

## 2. 检查构建内容

![构建路径](../../../images/build-flow.svg)

正式包包含 `package.json`、本包 `mod/*.dll`、本地化和必要的图片、索引、音乐，以及工坊生成的哈希。它不应含游戏 API/Core 引用、`.tmode-sdk`、`source/bin`、`source/obj`、快照、私人报告或存档。不要直接修改 Builds 或 Installed 的文件，任何内容变化都应回到 Sources 重建。

构建哈希表示精确文件内容，不认证作者身份，也不是数字签名。改动包会改变精确哈希和信任确认。代码模组以游戏进程权限执行，发布说明应准确说明用途与所需权限。

## 3. 使用游戏发布准备页

在开发页打开发布准备，选择待发布工程/构建，填写名称、描述、更新说明、标签和可见性，提供通过校验的预览图。当前流程的详细字段与更新步骤见[发布总览](../04-testing-and-publishing.md)。

先执行本地准备校验并查看诊断，修复资源与清单问题。若只导出包，记录导出成功即可；不要称其为 Steam 上传成功。

## 4. 单独验收线上流程

在已登录 Steam 的可发布游戏环境里提交。若要求接受创意工坊协议，通过 Steam 页面完成，再检查条目实际可见性。更新应复用原条目，确认新版本、预览与说明一致。

用订阅下载后的版本验证安装、启用、完整重启、内容、语言与玩法。开发电脑已安装的本地版本可能掩盖线上缺文件，因此先确认实际加载来源。需要迁移存档或兼容旧版本时，查[版本说明](../reference/versions.md)，先保留可恢复记录。

## 验收与下一步

- 包里只有可发布内容，哈希校验通过，重新安装能加载。
- 版本、入口、资源与说明对应，实际玩法有记录。
- 本地导出、线上提交、条目可见、订阅下载分别有证据。

发现问题先用[排错指南](../troubleshooting.md)。维护双语教程或提交文档改动时遵守[贡献说明](../../../CONTRIBUTING.md)。
