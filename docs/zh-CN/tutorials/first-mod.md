# 运行并修改你的第一个模组

[English](../../en/tutorials/first-mod.md) · [目录](../README.md)

这一课先做一件小事：让游戏加载一件名为“旅者遗物”的宝物，再把它的进场护盾从 2 改为 4。你会在图鉴里看到自己的修改。下一课再把它放进能玩的关卡。

## 开始前准备

- **MiniHero**：本教程使用支持 C# 模组的 Windows 游戏版本，当前接口索引为 Mod API 1.11.0；各课说明所需最低版本。更新游戏后再开始；具体版本限制见[版本页](../reference/versions.md)。
- **代码编辑器**：用你熟悉、能够编辑 C# 文件的编辑器打开项目。源码文件是普通文本，不能用 Word 保存。
- **.NET SDK**：用于把 C# 编译成游戏能加载的 DLL。若尚未安装，从 [Microsoft 的下载页](https://dotnet.microsoft.com/download)选择适合系统的 **SDK**；仅安装 Runtime 不够。

安装后重新打开终端或 PowerShell，输入：

```powershell
dotnet --version
```

看到一个 SDK 版本号即可继续。如果提示找不到 `dotnet`，先关闭并重新打开终端；仍不行时检查 SDK 是否安装成功。此时不用安装 Unity、下载游戏源码或运行本仓库的 Python 工具，也不用准备图片和音乐。

## 1. 创建一个练习项目

1. 启动游戏，点击主菜单左下角的交叉工具按钮，进入“冒险工坊”。
2. 打开“开发模组”，点击“新建 C# 项目…”。
3. 填写下表，确认创建。

| 输入框 | 本课填写 | 是什么 |
| --- | --- | --- |
| 包 ID | `local.alice.lantern-trail` | 模组的技术标识；后面的示例代码使用这个值 |
| 显示名称 | 提灯之旅 | 你在游戏里看到的项目名 |
| 作者 | 你的名字或昵称 | 显示在模组资料中的作者名 |

如果已有同 ID 项目，先确认它是不是自己的旧练习。可以继续使用，或选另一个包 ID；不要覆盖不清楚用途的项目。使用其他 ID 时，下一步需要相应调整两处代码。

![冒险工坊英文界面，开发模组位于中间一行](../../../images/ui-workshop-overview-en.png)

英文界面对应 **Adventure Workshop → Develop Mods → New C# Project…**。截图中的 **Develop Mods** 就是“开发模组”。

在新项目那一行点击“打开源码”。打开的文件夹就是接下来要编辑的**模组项目根目录**，也称 `Sources/<packageId>`。看到这些文件就找对了：

```text
package.json             模组资料和版本
source/
  ModEntry.cs            本课编辑的 C# 源码
  … .csproj              游戏生成的编译设置
localization/
  zh-Hans.json           中文名称和说明
  en.json                英文名称和说明
```

后文的 `source/ModEntry.cs` 等路径都从这个文件夹开始，不是在游戏安装目录里找。还没有 `mod/*.dll` 是正常的，第一次构建后才会生成。找不到文件时对照[操作配图](../reference/visual-walkthrough.md)。

## 2. 放入本课的入门代码

游戏已经生成可运行的入门宝物。这里换用教程的统一版本，方便后面增加角色和关卡时使用同一个 `ModEntry.PackageId`。

1. 用代码编辑器打开项目中的 `source/ModEntry.cs`。
2. 打开[本课源码](../../../templates/zh-CN/01-entry-and-config.cs.txt)，复制**全部代码**，替换 `ModEntry.cs` 的原内容。不要把旧入口接在新代码后面。
3. 如果包 ID 正好是 `local.alice.lantern-trail`，直接保存即可。使用其他 ID 时，先将示例里的 `PackageId` 字符串换成自己的包 ID，并将 `namespace LocalAliceLanternTrailMod` 换成创建项目时生成的命名空间。

不知道自己的命名空间时，先看原 `ModEntry.cs` 的 `namespace`，或查看 `package.json` 的 `codeEntryPoint`：最后的 `.ModEntry` 之前就是命名空间。保留原 `.csproj`、`codeEntryPoint` 和 `codeAssembly`，不用手动配置编译。比如本课完整入口是 `LocalAliceLanternTrailMod.ModEntry`。

源码链接以 `.cs.txt` 结尾，是为了便于在浏览器阅读。你要保存的目标仍是项目中的 `ModEntry.cs`，不要另存成 `ModEntry.cs.txt`。复制时只取代码，不把网页标题或链接一起粘进去。

这段代码里有一个入口 `ModEntry`，以及一件宝物 `StarterRelic`。宝物名称取自项目里的翻译表；描述和效果都使用 `BaseValue × 等级`。现在的 `BaseValue` 是 2，一级就会显示 2 点护盾。

## 3. 在游戏里找到这件宝物

1. 保存文件，回到“开发模组”。
2. 在自己的项目行点击“构建并安装”，等到安装成功。失败时先看自动打开的诊断报告，按[排错指南](../troubleshooting.md)处理第一条错误。
3. 到“管理模组”确认这份模组已启用；若出现代码信任提示，核对它是自己刚创建的包再继续。
4. 完整退出并重新启动游戏，打开宝物图鉴。
5. 角色筛选选“全部角色”，搜索“旅者遗物”。英文界面搜索 **Wayfarer's Relic**。

找到后，一级说明应该是“进入场景时获得 2 点护盾”。这表示你的项目已经被游戏加载。图鉴只是查看内容，此时还没有把宝物发给角色；实际获得它会在[宝物课](treasure.md)完成。

图鉴左下方的箭头切换**品质**，不会提高等级。本课各品质的数值相同，一级都显示 2。可以先保持当前品质，不用逐个切换。

没有搜索结果时，先检查模组是否启用、安装是否成功、搜索语言是否对应。不要等随机宝箱抽到它；图鉴检查不需要随机抽取。

## 4. 修改一次并重新验证

回到同一个 `source/ModEntry.cs`，找到：

```csharp
public override int BaseValue => 2;
```

将这里的 `2` 改成 `4`，保存。接着打开**项目根目录**的 `package.json`，把 `version` 的值从 `0.1.0` 改为 `0.1.1`。保留双引号和原来的逗号；如果已经用过 `0.1.1`，就在当前版本上再递增。包 ID 不变。

回游戏再次“构建并安装”，确认成功后完整退出、重新启动。在图鉴里重新搜索这件宝物，一级说明应变为“进入场景时获得 4 点护盾”。不用手改说明里的 `{0}`，代码会用同一公式填入新数字。

以后修改内容再安装，都需要先递增包版本。提示“相同版本已有不同内容”时，是安装被拒绝了，先改版本再重新构建。只重启不能修复这条错误。

如果仍显示 2，依次检查：改的是“打开源码”进入的项目吗？文件保存了吗？新版本安装成功了吗？所有游戏进程都退出了吗？同进程“重载内容”不会卸载已经加载的 C# DLL。

## 你现在完成了什么？

你已经创建了模组、把源码编译并安装进游戏，还能通过改代码改变宝物说明。保留这个项目，继续[制作第一个固定关卡](stage.md)，让游戏里出现一场你能亲手通关的冒险。
