# 建立可复现的玩法测试与错误报告

[English](../../en/tutorials/debugging.md) · [Index](../README.md)

教程修订 4 · Mod API 1.8.0 · 2026-10-14


目标：把“编译成功但没效果”拆成注册、出场、触发、计量、结算、重置六个可检查步骤。前置：[首课](first-mod.md)；用[固定关卡](stage.md)和[指定奖励](treasure.md)构建只含必要内容的测试牌场。它是自己的工坊源码测试，不要求 Unity 工程。

## 1. 固定输入，记录差值

选固定角色、固定列、固定奖励、明确等级与品质。移除不相关宝物。记录触发前后生命、护盾、属性、金币、回合、牌列与计数；显示结果和真实状态分开。只写“总护盾 10”不足以判断本宝物有没有加 3。

## 2. 每种内容的最小验收

| 内容 | 至少覆盖 |
| --- | --- |
| 宝物 | 获得、升级、品质值、重复预览、叠加、次数上限、换场景、读档 |
| 招式 | 次数 0／1／上限、空目标、多个目标、自动触发、恢复次数 |
| 敌人 | 两实例独立计数、防御、零实际伤害、死亡与首领奖励 |
| 道具 | 直接／目标使用、明牌目标、治疗修正、移除与使用通知 |
| 抉择 | 打开无副作用、支付、重复点击、失败回滚、链式取消、读档 |
| 冒险 | 入口、角色名单、每个出口、整备、最终胜利、循环终止／续接失败 |
| 页面／素材 | 返回原菜单、缺资源、切语言、原字号控件、裁切、声音全局设置 |

最低值、上限和刚好够／差 1 的资源边界，比继续加十个正常案例更能暴露规则错误。随机内容需固定种子，记录操作序列；仅相同种子但换操作不保证相同结果。

## 3. 分层定位第一处失败

不能编译先找第一条编译错误，不猜插件或 UI；加载失败查包 ID、完整入口、API、哈希和重复 ID；不出场查注册后是否加入角色池／关卡；未触发查事件和真实动作；数值不对查 requested、共享累加字段和取整；只第二次错查实例状态、上限与重置。对应具体症状见[排错页](../troubleshooting.md)。

## 4. 可复制报告

```text
Guide revision / API / package version:
Lesson and step:
Seed / character / difficulty / quality / level:
Files changed and registered IDs:
Action sequence:
Before -> expected -> actual:
First diagnostic code and location:
Build / load / gameplay / save / UI / Steam: passed, failed, or not run
```

只附最小相关源码和诊断，移除个人路径、账户、存档和开发引用。报告具体 code，不只截最后一行“失败”。不能把本地安装、同进程重载、完整重启、Steam 提交混成“都通过”。

## 5. 改后复测范围

改显示文本检查两语和版面；改数值检查描述、边界、实际效果；改事件或状态检查预览、重置与读档；改入口／引用检查完整重启和注册。每次重建安装递增包版本。维护者可跑文档工具，但文档链接通过不能替代玩法验收。实机 Unity 验证只使用已打开的正式 Editor，教程作者无需安装或复制 Unity 工程。
