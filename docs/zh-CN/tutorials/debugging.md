# 模组没按预期运行时，怎么找问题

[English](../../en/tutorials/debugging.md) · [目录](../README.md)

“编译成功了，但进游戏没效果”可能发生在几个不同步骤。先找最早出错的一步，会比同时改源码、图片和关卡更容易解决。

这篇用你已经完成的[首课](first-mod.md)、[固定关卡](stage.md)和[领取宝物](treasure.md)作例子。只需要自己的模组项目和游戏。

## 1. 先对照你看到的现象

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 构建失败 | 第一条编译错误的文件和行号 | 修它，再重新构建 |
| 图鉴没有宝物 | 安装成功、模组启用、完整重启、搜索语言 | 查[加载排错](../troubleshooting.md) |
| 图鉴有宝物，但宝箱没抽到 | 角色候选池是否匹配，或只是随机没抽到 | 用领取奇遇直接给宝物 |
| 领到遗物却没加盾 | 是否已经进入下一个场景 | 进场后才领取，要下次进场才触发 |
| 改了 4，游戏仍显示 2 | 文件是否保存、版本是否递增、新构建是否安装成功 | 完整退出再重启，并新开局 |
| 第一只狼受伤，第二只也变强 | 计数是否放在共享对象或 `static` 字段上 | 改为每张卡自己的状态 |

更多具体错误码看[排错指南](../troubleshooting.md)。先解决第一处失败，再往后检查。

## 2. 用一场小练习隔离问题

先保留一个角色、一种奖励、一个要检查的效果。把内容放到固定牌列，不等随机抽取。记录操作前后数值，例如：

```text
使用前：护盾 0，已领取一件一级旅者遗物，BaseValue 为 4。
操作：击败第一场守卫，点击出口，通过整备进入第二场。
预期：进场护盾增加 4。
实际：护盾仍为 0。
```

这个记录能把检查缩小到“进场效果”。只说“护盾不对”，别人还不知道你是否拿到了宝物、是否进入新场景、是否受伤消耗了护盾。

随机关卡还要保留种子、难度和相同操作顺序。相同种子下换一种操作，不一定得到同样的后续随机结果。

## 3. 修改后再试哪些情况

| 你改了什么 | 回游戏试什么 |
| --- | --- |
| 名称或说明 | 中英文都能读，参数变成正确数字，文字没有被截掉 |
| 数值或公式 | 说明和真实收益一致，最低值和上限符合预期 |
| 计数或触发时机 | 第一次、最后一次、超过上限、进入下一场景 |
| 敌人状态 | 两只各自变化，新建敌人从初始值开始 |
| 付费选项 | 金币刚好够、差 1、不重复扣费 |
| 多场景流程 | 每个出口可达，最后能胜利，继续游戏能接着玩 |
| 页面或素材 | 按钮可用，能回原菜单，图片和声音在游戏里正常 |

不用为改一个名字把整张表全部重做。按变化选相关项目。重新安装改过的内容前递增版本；C# 变化完整重启。

## 4. 把问题发给别人或 AI

可以复制这份短模板：

```text
教程页面和步骤：
游戏/API 版本、模组包 ID 和版本：
我改的文件与代码：
重现步骤：
预期结果：
实际结果（含操作前后数值）：
第一条错误及文件行号（没有错误就写“无”）：
```

只提供相关源码和必要报错。分享前删去私人路径、账号和其他个人内容；不要发送整份游戏 DLL 或存档。构建失败时，第一条 `error CS...` 通常比最后一行“构建失败”有用。

如果请 AI 修改，告诉它先解释错误原因，再改最小相关部分。一次修好一个问题后回游戏复试，避免它把整个能运行的项目重建一遍。提问方式见[用 AI 帮你制作模组](../ai-authoring.md)。
